# Release validation boundaries

The P3 entry runs accepted-baseline identity/regression mapping, clean wheels and offline installation, the original 138 behaviors plus new lifecycle/platform cases, actual optional MCP stdio, nonempty accepted prior/current installed binaries, backup/restore/rollback/reinstall, independent installed UMUH-like rehearsal, bounded extraction/accounting and fresh pinned eShop workflow. Each check has one run/source/package identity and hashed raw artifacts. Failed/incomplete/stale/mixed/tampered evidence cannot produce a qualified profile.

The nonempty upgrade fixture includes canonical graph/relationships, revisions/receipts, imported/pending/rejected/deferred queue work, stale prepared and committed-but-unacknowledged plans, positive observation metadata, completed/interrupted runs, request/usage history and accepted-before-ack outbox. Actual prior accepted wheels generate it, new installed binaries preserve it, compatible old code/data rollback and reinstall are checked. Maintenance fault tests kill real processes around staging/rename/commit boundaries; source is not reset.

A 183-file three-project fixture measures actual extraction per chunk, returned bytes and completed-resume duplication. Whole-snapshot enumeration/hashing remains distinct from bounded extraction and is documented. Metrics include all Main/role/provider and process attempts, unknown outcomes and cache/reasoning subsets without invented zero or efficiency claims. The distribution has pure-Python core wheels; optional MCP is pinned online, native SDK is separate and checksum-verified when downloaded.

Only explicitly executed profiles may be GO. Windows needs native NTFS/process/PowerShell 5.1 and installed rehearsal evidence; missing runner/result access yields NO_GO. Live OpenCode/model/private MCP remain separate optional qualifications. Source-based lexical facts are partial syntax observations, not compiler/runtime/business explanations. Trusted build hooks are not an OS sandbox. Source-root relocation/active cross-OS migration, production deployment and public publication remain outside this release verification.

The rehearsal pins native SDK selection with a project-local global.json (10.0.404, rollForward disabled), preserving any newer installed SDK. eShop reports the SDK resolved from its actual project directory. SDK/global.json and project host policy files are protected Coding inputs; selecting a new SDK is explicit user configuration.
