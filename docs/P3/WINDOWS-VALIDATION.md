# Native Windows architecture and qualification

Implementation uses CreateFileW execution ownership denying read/write sharing (FILE_SHARE_DELETE permits the exact fenced metadata-directory replacement), explicitly inherited by the isolated supervisor and direct recipe process. Byte-range LockFileEx shared/exclusive locking coordinates maintenance and ordinary transactions. No unlocked marker substitutes for a lock. Quiescent maintenance also checks durable pending native process ownership.

The supervisor creates a unique named Job Object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE, creates the recipe process suspended, assigns it to the job, persists process creation FILETIME/job/host provenance, then resumes its main thread. Descendants stay in the job; cancellation/timeout uses TerminateJobObject and verifies ActiveProcesses=0 before returning/releasing ownership. Supervisor death closes its job handle and kills descendants; the persisted job fence prevents reuse while the abandoned job remains active. Recovery opens only that recorded unpredictable job name and verifies live child identity/membership. No image-name taskkill or process-wide dotnet/Python termination is used. Linux retains inherited flock/process groups and adds pidfd-bound child termination and abandoned-group fencing.

Process receipts carry platform and boot/host hashes plus process creation identity. Historical/foreign receipts cannot authorize native termination. Unknown legacy pending process ownership refuses rather than guessing. Completed historical status remains inspectable. Store/run identity stays root-bound; raw copy/active-state relocation across root/OS is unsupported.

Native paths accept normal absolute drive paths, normalize case in project identity/protected recipe inputs and support spaces/Unicode. UNC/device/drive-relative, ADS, reserved names, trailing dot/space and short-name tilde aliases are explicitly refused before access. Ancestor symlinks, junctions/other reparse points and hardlinked files are rejected. Locked-file replacement returns failure; no passing edit/gate is synthesized. Native tests record actual NTFS, OS/Python/architecture and Windows PowerShell 5.1. PS7 is not claimed.

Commands: `powershell -NoProfile -File scripts/verify-windows.ps1`; the native Actions job uses the same entry and built release wheels. All 138 logical regressions remain. Five original fork-only fixture setups now choose spawn on Windows with the same behavioral assertions; their Linux fork path is unchanged. The full suite runs on Windows; the named NativeWindowsSafety cases cover path aliases/junctions/locked targets, actual Job cleanup and worker death. The portable PlatformSafety supervisor-death and foreign-receipt cases run on both OSes. A required capability failure blocks Windows GO.

The source workflow is not native proof. QUALIFICATION.json requires matched source/package identity, actual Windows/NTFS/PowerShell 5.1 metadata, all required portable/native/install/lifecycle/rehearsal results, no required skips and current artifact hashes. If CI/runner/result access is unavailable, record NOT_RUN/BLOCKED with exact handoff and Windows NO_GO. Linux/WSL/Wine/mocks never count as a native pass. Current raw local/CI evidence is authoritative.
