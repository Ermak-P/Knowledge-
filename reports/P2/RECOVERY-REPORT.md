# Recovery

Production state persists request reservations, role frames and pending tool cursors. Filesystem intents precede writes and full receipts precede cursor advancement. Tests terminate real worker processes with os._exit at edit intent, source-written and tool-receipt windows; resume produces one logical patch and preserves file modification time after an acknowledged write. Intervening user bytes cause a conflict and remain intact. Provider-intent death remains unknown and charged; automatic inference retry is refused.

Actual recipe timeout kills its real child process. Killing the parent runner while a recipe runs preserves the inherited flock; a competing owner is refused, and resume validates process PID/start/group then cleans the supervisor and descendants. Cancellation interrupts provider waiting and recipe polling. Unknown cleanup does not release mutation ownership. This Linux process-group boundary is documented, not represented as an OS sandbox.

Execution-passed is durable before capture; accepted-before-ack process death deduplicates exact payload on restart. Busy capture retries delivery only, without replaying source writes. Concurrent retries preserve one queue identity. Corrupt/version-mismatched/project-copied state refuses safely without resetting data. Changes to config or source during verification invalidate authority. Known limits: individual file replacement, SQLite, remote inference and Knowledge are separate transactions; multi-file edits reconcile file by file; detached hostile host processes require external isolation. Failed/cancelled runs are terminal and retain all attempts; a new run requires deliberate task submission.
