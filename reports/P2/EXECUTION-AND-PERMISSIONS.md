# Execution and permissions

| Role | Tools |
|---|---|
| Main | read, search, knowledge, delegate, status, capability |
| Planning | read, search, knowledge, capability |
| Coding | read, search, knowledge, patch, capability |
| Building / Testing | read, recipe (own kind only), artifact, capability |
| Reviewing | read, search, knowledge, artifact, review, capability |

Authority comes from durable role frames, not provider role fields or prompts. Tests send unauthorized recipe/delegate calls, extra role arguments, parent/dot/build-policy/recipe-input/test/linked paths and reject before forbidden effects. The .NET denial evaluation leaves the source snapshot unchanged and records actual tool-denied events. No arbitrary command tool exists.

Multi mode starts each role with its assignment, selected Knowledge, scope, current gates and artifact references. Only its own completed tool groups are retained. Main receives concise summaries; its private marker is absent in all child requests. Persisted artifacts and progress survive context replacement. Single mode is a shared-reasoning-history baseline with the same role executor and gates; its review context may see older failures. Tests explicitly prune long Unicode history and measure complete serialized UTF-8 request sizes. Current-run run reports include per-attempt input sizes/hashes and per-role aggregates; comparison includes all delegated costs. Sequential scheduling is intentional for one local-model slot.

Recipes are trusted configured host programs. Harness does not sandbox arbitrary build hooks, nor claim native OpenCode or Windows enforcement. See P2-CONTRACTS.md for the precise host and source-profile boundary.
