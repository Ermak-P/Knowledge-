# Accounting and comparison

Current-run `application-run.json`, `repair-run.json`, `denied-run.json`, `capture-sessions.json` and `comparison.json` contain all Main/subagent request attempts, runtime roles, states, input bytes/hash, actual HTTP duration and raw reported usage. Metrics export includes input/output totals per invocation, unknown coverage, tool/action durations, process attempts, lease acquisition/wait and elapsed wall time. Agent parent durations include delegated time and are not additive. Provider/process sums are sequential components, not wall time; timestamps include waiting/paused time. Denied calls and failed recipes remain in events/actions. Failed/inflight requests retain unknown usage instead of invented zero.

The deterministic HTTP fixture reports 11 input + 7 output = 18 tokens, with cached=3 and reasoning=2 as subsets. These are synthetic values for testing aggregation, not inference cost measurements. Inconsistent totals/subsets become unknown. A mandatory reported-token budget refuses missing usage. Byte/context caps measure full UTF-8 serialization; max_tokens is a requested provider cap, not a local tokenizer guarantee. Monetary cost is unknown without a rate.

Comparison runs the same independently specified .NET repair task in two ordinary source copies with identical provider configuration, recipes, task, guarded tools and final gates. Single mode shares completed reasoning/tool groups across invocations; multi mode isolates them. Both include separate runtime Reviewing role cost. Bootstrap Knowledge is empty in both, no hidden warmed cache. Both execute actual C# builds/assertions. Success is reported before usage/time. Real quality/speed/token advantage: **NOT_ESTABLISHED**. Live inference, warm/cold cache efficacy and independent reviewer intelligence are not established by scripted decisions. Raw neutral or slower timings remain visible.
